# 体验中心历史对话：开发需求

2026-10-28。前端原型已在官网仓库实现（控制台 → 体验中心，右上角「历史对话」），对话暂存在浏览器里；正式版需要服务端保存。

## 现在的两个问题

1. **切换页面后当前对话丢失。** 用户离开体验中心再回来，对话被清空。原因通常是体验中心组件在切换时被卸载重建，对话只存在组件状态里。
2. **没有历史对话。** 之前的对话找不回来，换设备或刷新后也看不到。

## 要做到的效果

- 切到其他页面再回来，当前对话原样保留。
- 刷新页面、重新登录、换一台电脑，都能看到之前的对话。
- 右上角「历史对话」打开右侧列表：按「今天 / 昨天 / 近 7 天 / 更早」分组，显示标题、所用模型、时间；可搜索；点一条恢复；可删除（两步确认）。
- 体验中心空白页显示最近 3 条对话，点即恢复。
- 「新对话」开始一条新的，之前那条自动留在历史里。

## 数据结构

**conversations**

| 字段 | 说明 |
|---|---|
| id | 对话 ID |
| user_id | 归属用户。企业成员的对话只归本人，管理员也看不到 |
| title | 默认取第一个问题的前 30 个字，可改名（二期） |
| models | 本次对话用的模型列表；对比模式下 1–3 个 |
| params | 温度、Top-P、最大输出词元、思考预算、系统提示词 |
| created_at / updated_at | 列表按 updated_at 倒序 |
| deleted_at | 软删除 |

**messages**

| 字段 | 说明 |
|---|---|
| id | 消息 ID |
| conversation_id | 所属对话 |
| model | 对比模式下区分是哪一列 |
| role | user / assistant / system |
| content | 内容 |
| input_tokens / output_tokens / cost | 每条回答的用量与费用，和使用日志同一口径 |
| ttft_ms / tokens_per_s | 首字时延、速度，用于对话下方的指标栏 |
| created_at | 时间 |

## 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/playground/conversations?cursor=&q= | 列表，分页，支持按标题和内容搜索 |
| POST | /api/playground/conversations | 新建，第一次发送时调用 |
| GET | /api/playground/conversations/{id} | 取一条对话的全部消息，用于恢复 |
| POST | /api/playground/conversations/{id}/messages | 发送并流式返回回答；回答完成后写入用量 |
| PATCH | /api/playground/conversations/{id} | 改标题、改模型、改参数 |
| DELETE | /api/playground/conversations/{id} | 删除（软删除，30 天后清除） |

## 前端改法

- 当前对话 ID 放在地址或 sessionStorage 里。进入体验中心时有 ID 就拉取并恢复，没有就显示空白页。
- 切换控制台页面时不要销毁体验中心的状态；或者回来时按当前对话 ID 重新拉取。
- 发送第一个问题时先建对话，拿到 ID 后再发消息；之后每条消息挂在这个 ID 下。
- 原型代码位置：官网 index.html 中「体验中心（2026-10-14 第二版）」脚本块，函数 `hload / hsave / hopen / hrender`；把本地存取换成上面的接口即可。

## 规则

- 每个用户最多保留 100 条对话，超出按最旧的自动清理；或按 90 天保留期清理，二选一，待定。
- 删除对话不影响已产生的账单和使用日志。
- 隐私政策要补一句：体验中心对话内容会保存在账号下，用于用户查看历史，用户可随时删除。
- 对比模式：一条对话里多列，每列的用户问题相同，回答分别存。
