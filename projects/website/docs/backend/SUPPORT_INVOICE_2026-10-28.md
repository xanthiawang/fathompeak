# 控制台「支持」与「发票」：开发需求

2026-10-28。前端原型已在官网仓库实现：控制台左下角「支持」进入支持页；侧栏「账户」组新增「发票」。工单和开票记录目前只存在页面内存里，需要接后端。

## 现在的问题

1. 正式平台左下角「支持」链接到 `#docs`，进去是空页面。
2. 用户充值后余额没变化时，找不到任何联系方式。
3. 开票表单藏在「钱包与账单」最底下，而且只有企业管理员能看到，个人用户没有开票入口。

## 支持页

**入口**：控制台左下角「支持」；钱包页「充值后余额没变化？联系我们」；发票页「开票信息填错了或需要红冲，联系我们」。

**页面结构**（从上到下）：
1. 四个常见问题入口：充值未到账、开发票、调用报错、账号与登录。点了跳到对应的表单或问答。
2. 充值未到账表单：
   - 充值订单：从该用户最近 10 笔充值记录里选；不在列表里可以手填订单号。
   - 付款方式：支付宝 / 微信 / 对公转账。
   - 付款金额、付款截图（图片）、联系方式（手机号或邮箱，默认带出账号绑定的）。
3. 联系我们：邮箱、电话，可复制。企业微信客服二维码待公司提供后加在这里。
4. 我提交的问题：时间、类型、内容、状态（待处理 / 处理中 / 已解决）。
5. 常见问题：401、429、余额用完、换手机号、退款。

**后台**：工单进运营「待办」，类型「充值未到账」，可在超管里查看截图、对照支付流水、手动补入余额并回复用户。补余额要写审计日志。

**接口**

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/support/tickets | 提交工单（类型、订单号、付款方式、金额、截图、联系方式） |
| POST | /api/support/uploads | 上传截图，返回文件 ID |
| GET | /api/support/tickets | 我的工单列表 |
| PATCH | /api/admin/support/tickets/{id} | 运营改状态、回复、关联补款记录 |

**自动核对（建议）**：提交时后端先用订单号查支付渠道。已付款但没入账的，直接补单入账并把工单标为已解决；查不到的再转人工。

## 发票页

**入口**：侧栏「账户」组「发票」（个人用户、企业管理员可见；企业成员不显示，由管理员开票）；钱包页「去开发票」；支持页「开发票」。

**规则**
- 只能按已支付成功的充值订单开票；赠送额度、代金券、兑换码不开票。
- 可开票金额 = 已支付充值 − 已开票 − 已退款。
- 一张发票可以合并多笔充值；一笔充值只能开一次。
- 个人抬头：只要姓名，开普通发票。
- 企业抬头：公司全称 + 纳税人识别号；可选普通发票或增值税专用发票，专票另需开户行及账号、注册地址及电话。
- 企业账户默认选「企业」，抬头带出合同签约主体。
- 开票后需要改信息，走红冲重开，由财务处理。

**接口**

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/invoices/available | 可开票的充值记录和可开票金额 |
| POST | /api/invoices | 申请开票（订单号列表、抬头类型、发票类型、抬头、税号、专票信息、接收邮箱） |
| GET | /api/invoices | 开票记录：时间、抬头、类型、金额、状态（开票中 / 已开具 / 已红冲）、PDF 下载地址 |
| GET | /api/invoice-titles | 常用抬头，下次自动带出（二期） |

**财务侧**：申请进入「财务工作台 · 待办 · 开票」，开具后上传 PDF 或对接电子发票服务，系统发邮件并把状态改为已开具。
