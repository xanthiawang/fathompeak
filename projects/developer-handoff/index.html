登录与身份接入

官网登录分「个人登录」和「企业登录」两个入口。个人账号和企业账号是两个账号，分别登录；后台是同一套界面，按登录的身份显示，后台里不切换身份。前端界面和显隐逻辑已经上线，开发要做的是：两套登录接口、身份接口、成员与邀请、开户申请。

2026-10-15 第二次修订：回到两个登录入口（替代上一版「一个入口、左上角切换组织」）。后台去掉个人 ↔ 企业切换，左上角只显示当前账号和身份；成员页保留邀请链接；不需要「一人属于多个组织」的组织成员表。

一句话：入口决定查哪类账号，账号决定进哪个后台。个人账号 = 手机号或邮箱；企业账号 = 工作邮箱，由管理员添加或通过邀请链接加入，属于一个企业。

开发主要工作：① 个人验证码登录；② 企业登录（工作邮箱 + 验证码，可选密码）；③ 两个入口之间的提示与免二次验证票据；④ GET /me 返回身份；⑤ 成员、邀请链接、开户申请、开通企业的接口；⑥ 员工登录与权限隔离。

登录怎么派发

四个后台是同一套界面。前端拿到 /me 后把角色写进 me.role，roleApply() 按元素上的 data-roles 显示或隐藏菜单与页面，侧栏分组名、概览的「开始使用」、右栏和额度名称也按角色变。后台里没有切换：要用另一个账号，退出后从另一个入口登录，账户菜单里写明了这一点。

同一个人既有个人账号又是企业成员时，是两个账号：Key、余额、日志各自独立，不互相迁移。

四条账号规则

1. 个人账号与企业账号分开

  • 个人账号：手机号或邮箱，验证即登录，没有就新建。只在「个人登录」里注册。
  • 企业账号：就是工作邮箱，属于一个企业。不能自己注册：由管理员添加，或通过邀请链接加入；管理员账号在沐仞开通企业时建立。
  • 企业账号第一次用邮箱验证码登录，之后可以设密码；忘记密码直接用验证码登录，不用找管理员重置。
  • 同一个邮箱可以同时有个人账号和企业账号，按登录入口区分。

2. 成员怎么加入

  • 按邮箱添加：管理员在「成员」页填工作邮箱和角色，成员表建一条「待加入」并发邮件；对方在「企业登录」用这个邮箱验证码登录即加入。
  • 邀请链接：管理员复制链接发到工作群；同事打开后进企业登录页（显示企业名），用自己的工作邮箱验证就以成员身份加入。管理员可以随时重置链接，旧链接立即失效。
  • 成员被移除时，他的企业账号停用，他创建的 Key 同时失效；他的个人账号不受影响。

3. 企业自助申请，运营一键开通

  • 官网「企业合作」的「联系销售」表单只留公司、联系方式、需求（选填）三栏；勾选「同时申请开通企业账户」后才出现「工作邮箱」，此时必填。
  • 勾选的提交生成一条开户申请，出现在超管「用户与组织 › 企业开户申请」。运营点「开通」会带入企业名称和管理员邮箱，确认合同价与结算方式后开通。
  • 开通后给管理员邮箱发通知；对方在「企业登录」用这个邮箱验证码登录即可。

4. 两个入口互相提示

  • 提示只在验证码通过之后出现，避免别人试出某个邮箱有没有注册。
  • 在个人登录验证通过，但这个邮箱只有企业账号：不自动建个人账号，先提示「这个邮箱是企业账号，去企业登录」。点了切到企业登录并带上邮箱，凭刚才的验证结果直接进入，不用再收一次验证码。用户确实要个人账号的，可以选「仍然创建个人账号」。
  • 在个人登录验证通过，个人和企业账号都有：进个人后台，顶部提示「这个邮箱也有企业账号」，可点去企业登录。
  • 在企业登录验证通过，但这个邮箱没有企业账号：提示「这个邮箱没有企业账号」，有个人账号的给「去个人登录」；不建任何账号。

{
  "kind": "personal | org",             // 从哪个入口登录的账号
  "email": "lin@company.cn",            // 个人账号也可能是 "phone": "138****0000"
  "role": "personal | admin | member",
  "org": { "id": "org_1", "name": "企业名称" },   // 个人账号为 null
  "edu": "none | wait | ok",            // 教育认证状态（仅个人账号）

// 前端换算：me.role = role；me.org = org && org.name；me.type = kind === "org" ? "company" : "personal"

安全要求

  • 防账号枚举：发送验证码的接口对存在与不存在的账号返回同样的结果；入口提示只在验证码通过后出现。
  • 验证码：60 秒内不能重发，单个手机号 / 邮箱和单个 IP 都要限频，连续输错锁定一段时间，验证码短时有效。
  • 免二次验证票据：handoff_token 一次性、短时有效、只能换取同一个邮箱的另一类账号。
  • 账号隔离：个人账号与企业账号的 Key、余额、日志互不可见；企业账号只能访问本企业的数据，成员只能读写自己的 Key 和日志。
  • 员工入口：独立域名、限制访问 IP、强制两步验证；员工账号与客户账号隔离，客户登录接口不接受员工账号。
  • 会话：成员被移除或角色变化时，已登录会话在下次请求时刷新身份。
  • 审计：添加 / 移除成员、改角色、生成或重置邀请链接、开通企业、入账等管理操作写入审计日志。
